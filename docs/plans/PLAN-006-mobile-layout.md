# PLAN-006：手機版（響應式網頁）

## 目標

面試官會用手機直接打開正式網址。目前畫面幾乎只為桌機設計（整個 UI 只有行程頁側欄用到 `lg:` 斷點），手機上會出現擠在一起的標題列、太小的按鈕、只在滑鼠移過才出現的操作。這次讓同一個網址在手機瀏覽器（寬 375～430px）上看起來整齊、所有功能都能用手指操作，一週內完成。

## 非目標

- PWA（加到主畫面、離線、App 圖示）、原生 App
- 重新設計視覺風格或改功能行為；只改排版與觸控操作
- 建立 Playwright E2E 測試或視覺回歸測試（需要時另開 issue）
- 修正 #330 以外的既有 bug（發現就開 issue）
- 平板專屬排版（640～1023px 只要求不破版）

## 驗收條件

以下都在 375px 與 430px 寬、直向、淺色與深色模式檢查：

- 首頁、行程頁（含 `/view` 公開範例）、行程列表、帳號、垃圾桶、隱私權頁：沒有水平捲軸，文字與按鈕不被截掉或重疊
- 行程頁標題列在手機上收成一行：返回、列表／地圖切換、「更多」選單（設為公開、複製連結、下載 PDF、垃圾桶、已儲存的行程）；桌機維持現狀
- 主要可點的元素（按鈕、拖拉把手、步進器、選單項目）觸控範圍至少 44×44px
- 不依賴 hover：行程列表的刪除等只在滑鼠移過才出現的操作，在觸控裝置上直接可見
- 文字輸入框在手機上字級至少 16px，iOS Safari 點進去不會自動放大
- 對話框（地點詳情、垃圾桶、各種選擇器、整天編輯、重新規劃精靈）在手機上全螢幕或從底部滑出，內容可捲動，關閉按鈕一直看得到
- 拖拉：手機長按景點或餐點可以拖拉排序，一般上下滑動不會誤觸拖拉；拖拉中的預覽不超出畫面
- 地圖模式在手機上佔滿可用高度，可以切回列表；地圖彈出資訊不超出畫面
- 刪除景點的復原提示在手機上固定在畫面內看得到（併入 #330）
- 桌機（1280px）畫面與目前一致，不退步
- `npm run lint`、`npx tsc --noEmit`、`npm test`、`npm run build` 通過
- 使用者用自己的手機在正式網站實際操作一次：打開公開範例、生成一份行程、做一次拖拉與換景點

## 邊界情況

- 很長的城市名、景點名、路線（多城市麵包屑）：換行或截斷加省略號，不撐開版面
- 一天十個以上的站：拖拉時畫面自動捲動
- 螢幕鍵盤打開時：底部對話框的輸入框與按鈕不被擋住
- iPhone 瀏海與底部 Home 條：固定在底部的元素加安全區間距（`env(safe-area-inset-bottom)`）
- 橫向手機：不要求最佳化，但不能破版
- 列印成 PDF：既有的 `print:` 樣式不受影響

## 成本

- 開發與檢查全程用 `npm run dev:free`，不呼叫 Google 與 Claude。
- 截圖檢查：用已安裝的 `playwright` 套件寫一次性腳本（放 scratchpad，不進 repo），對 `dev:free` 截 375／430／1280px 的畫面。**例外**：切到地圖模式會用真的 Maps key 計費（#239），地圖畫面只截 1～2 次，跑之前先問（R1）。
- 驗收的最後一步（使用者在正式網站生成一份行程）會用真實 Google 與 Claude，約 US$0.25～0.45，由使用者自己操作。
- 公開範例使用者已準備好，這次不另外生成。

## 設計摘要

- 沿用 Tailwind 的 mobile-first：預設寫手機樣式，用 `sm:`／`lg:` 加回桌機樣式。不新增套件。
- 共用元件：一個 `ResponsiveDialog`（手機從底部滑出或全螢幕，桌機維持置中），取代各對話框各自寫的 `fixed inset-0`；一個簡單的「更多」選單（自己寫，不引入 UI 套件）。
- 觸控裝置的判斷用 CSS（`@media (hover: none)`、Tailwind 的 `pointer-coarse:` 等），不在 JS 偵測裝置。
- 拖拉沿用 `useItinerarySensors` 的 TouchSensor（長按觸發），只調整把手大小、預覽寬度與 `touch-action`。
- 先截一輪手機畫面列出實際問題，再依面試官最可能看到的順序修：公開範例行程頁 → 首頁表單 → 行程頁編輯 → 列表與帳號。
- 最優先是面試官點開公開範例（`/view`）不跑版：任務 1～3 先開一個 PR 合併上線，不等後面的任務。
