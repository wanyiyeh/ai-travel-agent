# ADR-0011：機場資料改用開放資料產生，人工清單只做覆寫

日期：2026-10-28
狀態：Accepted

## 背景

出發地與目的地只能從人工維護的 `AIRPORTS`（約 100 個國際機場）挑，每補一個機場要同時改五張表（城市與座標、國家、交通時間、貨幣、物價），漏一張就悄悄失效。朋友想去冰島找不到機場（#298）。要涵蓋全世界的中大型機場，就不能再靠人工。

## 決策

- **機場清單用 OurAirports**（公有領域）：只取有定期航班的大型與中型機場，約 3,200 個（2026-10：大型 1,152、中型 2,093）。很多觀光小島與區域城市是中型機場，只取大型會又有人找不到。
- **中文城市名、服務的城市、城市座標、國家、貨幣用 Wikidata**（CC0）：查不到中文名時顯示英文城市名。
- **各國物價水準用世界銀行的購買力資料**（CC BY 4.0，網站上標示出處）：物價表沒有的貨幣，以美元參考價換算。
- 由一支腳本把三個來源合成 JSON 資料檔提交進 git，執行時不連外部資料來源；每年重跑一次。
- 現有的人工清單保留，優先於生成資料：它的中文名、市中心座標與交通時間比較準。
- 首頁的完整機場清單在打開選單時才載入。

## 考慮過的替代方案

- 繼續人工維護，一次補到約 300 個：資料最可靠，但仍有人找不到，而且五張表要同步的問題還在。
- 所有有定期航班的機場（約 4,000 個）：多出來的大多是旅客很少直接飛去的小機場，中文名與城市對應的抽查量多一倍以上。
- 使用者輸入任何城市，用 Google Places 找座標：每個新城市都要付費查詢，城市名也是 Google 內容，不能存（ADR-0004）。
- 用 OpenAI 翻譯中文城市名：要付費，翻錯也難發現；Wikidata 的名稱有人維護。
- 物價表沒有的貨幣就不估價：使用者看到很多「未估算」；粗估比沒有好。

## 後果

- 新增一支資料腳本與兩個生成的資料檔；`IATA_COUNTRY_ZH`、`IATA_CURRENCY` 併入同一個查詢模組，不再各自維護。
- 以中文城市名反查機場代碼會遇到同名城市，同名時不猜。
- 新貨幣的費用是粗估，準確度低於人工物價表。
- 網站要標示世界銀行資料的出處。
- 資料每年要更新一次，步驟寫在 runbook。
